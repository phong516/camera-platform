Main Loop & Ownership

What g_main_loop_new / run / quit / unref each do to the reference count, how the lab8 client is wired, and the shutdown patterns for the client and the RTSP server. Compressed from Lesson 10.

The one sentence

A pointer is not an owner. new returns one owned reference; aliases copy only the address; run borrows with its own temporary reference; quit stops but does not free; unref decrements and frees at zero. One owned ref → exactly one unref.

API ledger

CallRef effectWhat it does / notes
g_main_loop_new(ctx, FALSE)+1 — yoursAllocates the loop; refs ctx (or the global default if NULL). Caller owns the return (docs).
g_main_loop_ref(loop)+1Adds an owner. The returned pointer is the same object (docs).
g_main_loop_run(loop)borrowIterates until quit. GLib takes a temporary ref for the call and drops it on return, so your ref count is unchanged (gmain.c).
g_main_loop_quit(loop)0Sets is_running = FALSE, wakes the context; run returns. Does not free (docs).
g_main_loop_unref(loop)−1At zero: frees the loop and drops its context reference (docs).
g_main_loop_get_context(loop)0Borrowed pointer; do not unref it.

Two objects, not one

ObjectRoleOwned by
GMainContextQueue of event sources: timers, fd watches, RTSP server socketsWhoever called g_main_context_new(); also referenced by every loop using it
GMainLoopRun/quit controller that iterates one contextThe caller of g_main_loop_new()
GSourceOne timeout/idle/fd source (g_timeout_add)The context; callbacks run when it is iterated

A context can only run in one thread at a time. Sources can be added/removed from other threads; the context's API is thread-safe. Source: The Main Event Loop.

The lab8 client in one screen

// media path — count access units, do not decode
rtspsrc latency=0 protocols=tcp ! rtph264depay ! h264parse
  ! appsink emit-signals=true sync=false name=sink

// app wiring
sink = gst_bin_get_by_name(GST_BIN(pipeline), "sink");  // full ref
g_signal_connect(sink, "new-sample", on_new_sample, NULL); // streaming thread
g_signal_connect(sink, "eos", on_eos, NULL);               // streaming thread
gst_object_unref(sink);

loop = g_main_loop_new(NULL, FALSE);   // one owned ref, default context
g_timeout_add(500, report, NULL);      // main thread
g_timeout_add(secs * 1000, quit_timeout, loop);
gst_element_set_state(pipeline, GST_STATE_PLAYING);
g_main_loop_run(loop);
g_main_loop_unref(loop);               // free after run returns
gst_element_set_state(pipeline, GST_STATE_NULL);
gst_object_unref(pipeline);

Client vs server — where appsrc lives

lab8client is a consumer only: rtspsrc → rtph264depay → h264parse → appsink. It has no appsrc. The server (labs/lab8-rtsp-recover.cpp) owns both halves of the bridge: the producer pipeline videotestsrc → x264enc → appsink(psink), and the RTSP media pipeline appsrc(vsrc) → h264parse → rtph264pay. The media — and therefore vsrc — is created on the first viewer; media-configure finds it by name, and the producer's new-sample callback restamps and pushes each buffer into it. No viewer = no appsrc; producer samples are dropped. No server = the client prints samples=0 and exits silently (it never polls the bus).

Correct patterns (copy-paste)

// 1. client / any process using the default context
GMainLoop *loop = g_main_loop_new(NULL, FALSE);
/* add sources */
g_main_loop_run(loop);
g_main_loop_unref(loop);

// 2. server with a private context (lab5-rtsp-server.cpp)
GMainContext *ctx = g_main_context_new();          // your ref
GMainLoop *loop = g_main_loop_new(ctx, FALSE);     // loop's ref on ctx
gst_rtsp_server_attach(server, ctx);               // adds server sources
g_main_loop_run(loop);
g_main_loop_unref(loop);                           // drops loop + its ctx ref
g_main_context_unref(ctx);                         // drops your ctx ref

// 3. server on the default context (lab8-rtsp-recover.cpp)
gst_rtsp_server_attach(server, NULL);               // default context
GMainLoop *loop = g_main_loop_new(NULL, FALSE);    // same context
g_main_loop_run(loop);
g_main_loop_unref(loop);                           // no ctx unref: none owned

Traps

SymptomCause / fix
LSan: “16 byte(s) leaked … g_main_loop_new”Missing g_main_loop_unref. At 16 bytes it is exactly the loop struct. Cosmetic at process exit, real on a server shutdown path.
GLib-CRITICAL: g_main_loop_unref: assertion 'ref_count > 0' failedUnref'd more times than owned. Count refs, not pointers; run does not consume yours.
Use-after-free in a timeout callbackSource outlived the loop. Keep the guint from g_timeout_add and g_source_remove() before unref; or attach to a private context and destroy it last. Docs.
Second GLib loop in the GUI threadQt/GTK own the main thread's loop. Integrate a GMainContext or run GLib loop on a dedicated thread; do not block the GUI loop.
RTSP server accepts nothinggst_rtsp_server_attach() only adds sources to a context. The context must be iterated — g_main_loop_run() is what makes the server live.
Per-profile loopOne loop + one context per application (or per dedicated thread). Profiles share the host's loop; they are not event-loop owners.

Why the local unref is the same call as the global

GMainLoop *mloop_local = g_main_loop_new(NULL, FALSE);  // ref 1 (yours)
mloop = mloop_local;                                    // alias, no ref
g_main_loop_run(mloop);                                 // +1 then -1 internally
g_main_loop_unref(mloop_local);                         // -1 → free

g_main_loop_unref(mloop) would be exactly the same decrement. The local is used because it is the owner variable; the global exists only so callbacks (which receive gpointer, not closures) can reach the loop. Better: pass the loop through signal/timeout user_data and delete the global.
