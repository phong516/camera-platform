Branching Elements

tee, queue, valve, bin & ghost pad — the elements that fan out the camera-platform pipeline. Compressed from Lesson 1 through Lesson 4.

The preroll gate (the one rule that explains most stalls)

Rule

A sink completes preroll only when it receives a buffer, GAP event, or EOS. Until every sink in the pipeline completes preroll, no sink renders, even in live pipelines that print PLAYING. Symptoms of one starved sink: all outputs stay empty / stuck at Pipeline is PREROLLING ....
Source: preroll design doc.

tee

Fans one stream out to N src pads. Every buffer goes to every pad, pushed sequentially in the pushing thread.

ItemDetail
Doctee · presence: always
Padsrequest src pads (src_%u), one per branch
allow-not-linkedreturn OK with no linked pads (default false)
Golden rule“One needs to use separate queue elements … in each branch … Otherwise a blocked dataflow in one branch would stall the other branches.”

queue

Thread boundary + bounded buffer. chain() returns immediately (unblocks the tee); a private src task drains buffers downstream.

PropertyDefaultNotes
max-size-buffers200whichever limit is hit first blocks (or leaks)
max-size-bytes10 485 760 (10 MB)
max-size-time1 000 000 000 ns (1 s)the practical slack in camera work: ≈30 frames at 30 fps
leakynoupstream drops oldest, downstream drops newest instead of blocking upstream

queue docs · for the multi-branch case multiqueue also exists.

valve

Runtime on/off switch. drop is writable at any moment; drop-mode only in NULL/READY.

drop-modeBehaviour when drop=true
drop-all (default)buffers and events dropped — starves the sink entirely
forward-sticky-eventsbuffers dropped; caps/segment forwarded — sink still gets no data
transform-to-gapbuffers become GAP events → sink can still preroll

valve docs. Note: downstream errors are ignored while drop=TRUE.

Starting closed at startup (valve drop=true before PLAYING) freezes the pipeline unless the starved sink is async=false: verified for appsink — plays normally, reopen clean (65 ms settle, full rate). NOT verified for filesink+encoder. With the default async=true the freeze is permanent — reopening the valve later does not rescue it. (labs/lab-async-appsink.cpp)

Where the freeze lives (state probes): live → pipeline parks at PAUSED → PLAYING (PAUSED does commit), starved sink at READY → PAUSED; non-live → pipeline READY → PLAYING. The flow wedges ~1 s in: the stopped branch's queue fills to its 1 s limit, the tee's sequential push blocks, the source thread freezes — all branches starve, and a later valve reopen has nothing to forward. Bus stays silent (no error): detect with a gst_element_get_state timeout watchdog. (labs/lab-preroll-states.cpp, labs/lab-stall-mechanism.cpp)

bin & ghost pad

A GstBin is a container that is itself an element — from outside it participates as a single element. A ghost pad exposes one internal pad on the bin (a proxy): the host links to the ghost, data flows to the internal target. (Lesson 3 · Lesson 4)

ItemDetail
DocsGstGhostPad reference · design doc
Create (1.28)gst_ghost_pad_new(name, target) → floating ref · then gst_element_add_pad(bin, ghost). gst_element_add_ghost_pad no longer exists.
Ownershipget_static_pad / request_pad_simple return full refs (you unref after use); the ghost refs its target; add_pad consumes the ghost.
Static binsafter attaching all ghost pads, call gst_element_no_more_pads(bin)
Runtime lookupgst_bin_get_by_name(bin, "pvalve") — scoped to the bin, so sibling bins may reuse internal names

identity (lab tool)

Passthrough used to fake a slow consumer: identity sleep-time=<µs> sleeps between buffers (500000 = 0.5 s per buffer ≈ 2 fps).

Verified lab recipes (copy-paste)

# tee + queues, 60 frames of 320x240 I420 → both files 6,912,000 B
gst-launch-1.0 -q videotestsrc num-buffers=60 ! videoconvert \
  ! video/x-raw,format=I420,width=320,height=240,framerate=30/1 ! tee name=t \
  t. ! queue ! filesink location=a.raw t. ! queue ! filesink location=b.raw

# the phase-2 topology as a prototype (10 s; hd.264 + sd.264)
timeout 10 gst-launch-1.0 -q videotestsrc is-live=true ! videoconvert \
  ! video/x-raw,format=I420,width=1920,height=1080,framerate=30/1 ! tee name=t \
  t. ! queue ! videoscale ! video/x-raw,width=1920,height=1080 \
    ! x264enc speed-preset=ultrafast tune=zerolatency key-int-max=30 ! filesink location=hd.264 \
  t. ! queue ! videoscale ! video/x-raw,width=1280,height=720 \
    ! x264enc speed-preset=ultrafast tune=zerolatency key-int-max=30 ! filesink location=sd.264

# inspect anything
gst-inspect-1.0 queue | grep -A3 max-size
gst-inspect-1.0 x264enc | grep -i bitrate

# C++: attach a profile bin to a tee (labs/lab3, labs/lab4)
GstPad *tee_pad = gst_element_request_pad_simple(tee, "src_%u");
GstPad *bin_pad = gst_element_get_static_pad(bin, "sink");  // the ghost pad
gst_pad_link(tee_pad, bin_pad);
gst_object_unref(tee_pad);
gst_object_unref(bin_pad);

# C++: flip a profile at runtime (valve inside the bin)
GstElement *valve = gst_bin_get_by_name(GST_BIN(bin), "pvalve");
g_object_set(valve, "drop", TRUE, nullptr);  // FALSE resumes
gst_object_unref(valve);

CPU rule of thumb (this machine, 720p30, x264enc ultrafast+zerolatency)

Pipelines runningCPU
1 encoder branch≈ 92 %
2 encoder branches≈ 182 %
2nd branch dropped at startup (async=false sink)≈ 95 %

Design consequences for camera-platform: queue on every branch · never start with a valve closed · drop only after preroll, mid-run drops are safe · if a profile must be absent from frame one, do not build the branch · profiles as config rows, one bin+ghost-pad ProfileBin per profile · queue closest to the tee (encoder work on its own thread), valve after the queue.
