Camera Platform · Lesson 0011

RTSP Frames into QML

The player decodes. The Quick scene presents.

Your mission: show a selected camera profile in CameraView.qml without making the UI depend on the server's GStreamer pipeline.

One boundary to keep clear

RTSP carries the encoded media from the server to the client. The client still needs a player to receive the stream, negotiate its media, decode video, and hand frames to a renderer. QML's job is the last part: place that renderer in the scene.

camera-profile ── RTSP/H.264 ──▶ MediaPlayer ── decoded frames ──▶ VideoOutput
      server                         Qt Multimedia                 QML scene

For the first experiment, use Qt Multimedia's MediaPlayer and VideoOutput. This fits the current architecture: the client speaks RTSP for media and HTTP for control; it does not link the server or reach into VideoPipeline. The exact RTSP support still depends on the Qt build, backend, codecs, and target platform, so a successful compile is not proof of playback.

Smallest useful QML probe

import QtQuick
import QtMultimedia

Item {
    MediaPlayer {
        id: player
        source: "rtsp://127.0.0.1:8554/hd"
        videoOutput: output
        onErrorOccurred: (error, errorString) => console.error(errorString)
    }

    VideoOutput {
        id: output
        anchors.fill: parent
        fillMode: VideoOutput.PreserveAspectFit
    }

    Component.onCompleted: player.play()
    Component.onDestruction: player.stop()
}

The URL above is the project's planned HD mount, not a working endpoint yet: the profile server is still ahead in the build. When you test against a real RTSP source, use an endpoint reachable from the client and check errorString, hasVideo, and playbackState. For live media, duration == 0 is normal.

Retrieval check

Which QML item paints frames in the scene?

VideoOutput is the presentation item; the player handles stream playback and supplies its video output.

What does a zero duration mean for a live stream?

Live streams have no fixed end time, so duration zero by itself does not indicate a playback error.

Your repo step

Prototype this probe in CameraView.qml using a reachable RTSP URL. Add Qt Multimedia to the CMake components and link Qt6::Multimedia; then test the exact runtime backend and codec you plan to deploy. Only after the probe renders frames should you move the URL behind a typed C++ backend property and connect it to the selected profile.
